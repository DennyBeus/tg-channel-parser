# Telegram Channel Parser

[English](README.md) | [Русский](README.ru.md)

Простой Python CLI-скрипт для экспорта постов из Telegram-каналов с фильтрацией по дате и экспортом в `txt` или `json`.

Благодаря CLI-интерфейсу и выводу JSON через `--stdout`, скрипт легко интегрируется в платформы автоматизации вроде n8n — достаточно вызвать его из ноды Execute Command и передать результат дальше по цепочке.

Отдельная благодарность автору [`kurigram`](https://github.com/KurimuzonAkuma/kurigram/tree/dev) за помощь в решении проблемы с парсингом постов, использующих стиль шрифта Quote.

## Что делает программа

- подключается к Telegram как пользователь (userbot session);
- читает историю канала;
- извлекает текст постов и подписи к медиа;
- извлекает inline-ссылки из text_link entities и вставляет их после якорного текста (с корректной обработкой emoji/UTF-16 смещений);
- сохраняет дату, текст, просмотры, общее количество реакций, ссылку на пост и имя канала;
- поддерживает парсинг нескольких каналов за один запуск;
- может ограничивать количество сообщений и удалять emoji из текста;
- может выводить результат в формате JSON прямо в stdout для пайпинга в другие инструменты.

## Библиотеки и почему `kurigram` здесь важен

В `requirements.txt` используются:

- `kurigram`
- `tgcrypto==1.2.5`
- `aiohttp==3.9.5`
- `requests`
- `python-dotenv`

### Ключевой момент о `kurigram`

В коде импорт выполняется как `from pyrogram import Client`, но в зависимостях указан `kurigram`.

`kurigram` предоставляет совместимый Telegram API client с интерфейсом в стиле Pyrogram, поэтому в коде используется привычный `Client`, а установка выполняется через `kurigram`.  
Этот client используется для:

- авторизации пользователя;
- получения информации о канале;
- чтения истории сообщений (`get_chat_history`).

`tgcrypto` нужен для ускорения MTProto-криптографии, а `python-dotenv` используется для загрузки переменных из `.env`.

## Требования

- Python 3.8+ (рекомендуется современная версия);
- Telegram API credentials: `API_ID`, `API_HASH`, `PHONE_NUMBER`.

Получить `API_ID` и `API_HASH` можно на [`my.telegram.org`](https://my.telegram.org/auth).

## Установка

```bash
pip install -r requirements.txt
```

## Настройка `.env`

Создайте файл `.env` в корне проекта:

```env
API_ID=123456
API_HASH=your_api_hash
PHONE_NUMBER=+79991234567
```

Также можно задать:

```env
DATA_DIR=./data
```

Если `DATA_DIR` не указан, по умолчанию используется `./data`.

## Как это работает пошагово

1. Вы один раз запускаете авторизацию (`--auth`) для создания сессии.
2. Скрипт сохраняет сессию в папке данных (`DATA_DIR/user`).
3. При обычном запуске он определяет канал(ы), читает историю и фильтрует сообщения по дате.
4. Текст нормализуется (удаляются лишние пробелы и пустые строки).
5. Inline-ссылки из text_link entities извлекаются и вставляются после якорного текста.
6. С флагом `-j` удаляются emoji.
7. Результат сохраняется в файл или выводится в stdout (`--stdout`).

## Использование

### 1) Авторизация (первый запуск)

```bash
python userbot.py --auth
```

### 2) Базовый парсинг всего канала

```bash
python userbot.py https://t.me/channel_name
```

### 3) Кастомный парсинг

По диапазону дат:

```bash
python userbot.py -s 01.01.2024 -e 31.01.2024 https://t.me/channel_name
```

Лимит сообщений:

```bash
python userbot.py -l 100 https://t.me/channel_name
```

JSON export:

```bash
python userbot.py -f json -o beus_research https://t.me/channel_name
```

Удалить emoji:

```bash
python userbot.py -j https://t.me/channel_name
```

Порядок от старых к новым:

```bash
python userbot.py -r https://t.me/channel_name
```

Вывод JSON в stdout (для пайпинга или быстрого просмотра):

```bash
python userbot.py --stdout -f json -l 10 https://t.me/channel_name
```

Несколько каналов за один запуск:

```bash
python userbot.py -f json -o combined https://t.me/channel1 https://t.me/channel2
```

Комбинированный пример:

```bash
python userbot.py -s 01.01.2024 -e 31.12.2024 -l 500 -f json -o export_2024 -j -r https://t.me/channel_name
```

## Аргументы CLI

- `channel` — один или несколько URL каналов (обязателен, кроме режима `--auth`);
- `-a, --auth` — режим авторизации;
- `-s START` — начальная дата в формате `DD.MM.YYYY` (по умолчанию: `01.01.1970`);
- `-e END` — конечная дата в формате `DD.MM.YYYY` (по умолчанию: текущая дата);
- `-o OUTPUT` — имя выходного файла (по умолчанию: `result`);
- `-f {txt,json}` — формат файла (по умолчанию: `txt`);
- `-l LIMIT` — максимальное количество сообщений на канал;
- `-r, --reverse` — записывать результат от старых к новым;
- `-j, --no-emoji` — удалить emoji из текста;
- `--stdout` — вывести JSON в stdout вместо сохранения в файл.

## Куда сохраняется результат

- Если указан только имя файла (например, `-o report`), файл сохраняется в папку `Downloads` пользователя: `report.txt` или `report.json`.
- Если указан полный путь, сохранение выполняется по этому пути.
- С флагом `--stdout` файл не создаётся — JSON выводится в терминал.

## Формат данных

Каждое сообщение содержит:

- `text` — текст поста или подпись к медиа (inline-ссылки из text_link entities вставляются в скобках после якорного текста);
- `date` — дата/время в формате `YYYY-MM-DD HH:MM:SS`;
- `views` — просмотры;
- `reactions_count` — общее количество реакций;
- `link` — прямая ссылка на пост (`https://t.me/channel/id`);
- `source_channel` — имя канала.

## Полезно знать

- Скрипт читает историю от новых к старым, а с `-r` разворачивает результат перед сохранением.
- Сообщения без текста пропускаются.
- Если по заданным критериям ничего не найдено, скрипт показывает предупреждение и не создаёт файл.
