# grabogram

[English](README.md) | [Русский](README.ru.md)

Парсер Telegram-каналов, который живёт на **твоём** сервере и управляется целиком из **Telegram-бота**. Один раз настроил — и больше никакого терминала: ты пишешь боту, бот парсит, и готовый файл `txt` или `json` прилетает обратно прямо в чат.

Внутри всё тот же честный CLI-парсер, что был тут с самого начала, — бот просто удобная оболочка вокруг него. Так что если ты любишь гонять JSON в n8n или в shell-скрипт, этот путь по-прежнему открыт (см. [Режим для своих: голый CLI](#режим-для-своих-голый-cli)).

Вся идея в одном: **поставил одним скриптом — и забыл, что сервер вообще существует.** Добавить прокси, перелогиниться, спарсить канал — всё с телефона.

> **Твои данные остаются твоими.** Весь код открыт. Сессии, выгруженные файлы и вообще всё лежит только на твоём сервере. Никуда ничего не уходит — нет никакого «нашего облака», из которого что-то могло бы утечь.

Отдельная благодарность автору [`kurigram`](https://github.com/KurimuzonAkuma/kurigram/tree/dev) за помощь в решении проблемы с парсингом постов, использующих стиль шрифта Quote.

## Что ты получаешь

- Telegram-бот, которым управляешь только ты — он привязан к твоему числовому Telegram ID.
- Команду `/parse` в двух вариантах: пошаговый мастер для спокойного использования и однострочная команда с флагами, когда точно знаешь, что хочешь.
- Экспорт в `txt` (по-человечески читаемый) или `json` (для машин), который приходит файлом прямо в чат.
- Фильтр по диапазону дат, лимит сообщений, фильтр по ключевым словам, удаление эмодзи и порядок от старых к новым.
- Перелогин прямо из бота (`/auth`), когда сессия протухла — вместе с 2FA — и ни разу не открывая терминал.
- Опциональную поддержку прокси для регионов, где Telegram заблокирован, или для платных прокси с авторизацией.
- Двуязычный интерфейс: 🇬🇧 English / 🇷🇺 Русский, переключается прямо в боте.
- Запуск в Docker. Один скрипт делает всё: ставит Docker, клонирует репозиторий, задаёт пару вопросов и поднимает контейнер.

А под капотом парсер:

- подключается к Telegram как пользователь (userbot session);
- читает историю канала, извлекает текст постов и подписи к медиа;
- вытаскивает inline-ссылки из `text_link` entities и вставляет их сразу после якорного текста (с корректной обработкой emoji/UTF‑16 смещений — это как раз самая капризная часть);
- сохраняет дату, текст, просмотры, общее количество реакций, ссылку на пост и имя канала;
- умеет парсить несколько каналов за один запуск, ограничивать число сообщений, убирать эмодзи и фильтровать по ключевым словам.

## Что нужно подготовить

Понадобятся три вещи:

1. **VPS** (подойдёт любой дешёвый Ubuntu/Debian), где можно выполнить пару команд. Установщик ты запустишь там *один раз*.
2. **Telegram API credentials** — `API_ID` и `API_HASH`. Бери на [my.telegram.org](https://my.telegram.org/auth) → *API development tools* → создай приложение.
3. **Токен бота** — открой [@BotFather](https://t.me/BotFather), отправь `/newbot`, следуй подсказкам и скопируй токен (вида `123456789:ABC-DEF1234...`).

Ещё пригодится твой **числовой Telegram ID**, чтобы бот понимал, кто его хозяин. Напиши `/start` боту [@userinfobot](https://t.me/userinfobot) — он покажет (просто число, без `@`).

И **номер телефона** того аккаунта, который будет читать каналы — парсинг идёт *от его лица*, так что он должен видеть нужные тебе каналы.

## Установка (по-простому)

На сервере запусти установщик одной строкой:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/DennyBeus/grabogram/main/install.sh)
```

Привычнее по-классике? Склонируй репозиторий и запусти скрипт руками — он делает ровно то же самое:

```bash
git clone https://github.com/DennyBeus/grabogram.git
cd grabogram
chmod +x install.sh
./install.sh
```

В любом случае скрипт сам:

1. Проверит `curl` и **поставит Docker**, если его ещё нет.
2. **Склонирует репозиторий** (или переиспользует папку, если ты уже внутри неё).
3. Проведёт тебя по созданию `.env` — спросит `API_ID`, `API_HASH`, номер телефона, токен бота, твой owner ID и, по желанию, прокси. Никакой ручной правки файлов.
4. **Соберёт и запустит** Docker-контейнер.
5. Сделает **разовый вход** для аккаунта-парсера: Telegram пришлёт код в приложение (или по SMS), ты вводишь его — и готово. Если у тебя 2FA, спросит пароль.

В конце увидишь короткую сводку с командами бота. Открывай своего бота в Telegram, жми `/start` — и ты в деле.

> Дальше **возвращаться на сервер для повседневной работы уже не нужно.** Протухла сессия? Перелогинься из бота. Нужен прокси? Он настраивается на этапе установки (или добавь позже, см. ниже). При перезагрузке контейнер поднимется сам.

## Работа с ботом

Открой бота, которого создал через @BotFather, и нажми **`/start`**. Получишь главное меню с переключателем языка и кнопкой «Помощь».

Четыре команды:

| Команда | Что делает |
| --- | --- |
| `/start` | Главное меню (язык + помощь) |
| `/parse` | Запустить парсинг — мастером или одной строкой |
| `/auth` | Обновить userbot-сессию (когда протухла) |
| `/cancel` | Отменить то, что начал |

### Мастер /parse

Просто отправь `/parse` без ничего — и бот проведёт тебя за руку, по одному вопросу за раз:

1. **URL канала** — например `https://t.me/durov`
2. **Период дат** — `01.01.2024-31.12.2024` или нажми **Пропустить**
3. **Лимит сообщений** — число или **Пропустить**
4. **Ключевые слова** — через пробел, для фильтра постов, или **Пропустить**
5. **Порядок** — *От старых к новым* / *От новых к старым*
6. **Emoji** — *Удалить* / *Оставить*
7. **Формат** — `txt` / `json`

Когда закончишь, бот выполнит задачу и положит файл с результатом прямо в чат. Ничего не надо качать с сервера, ничего не надо подчищать — старые временные выгрузки удаляются автоматически.

### Прямая команда /parse

Если уже знаешь, что хочешь, пропусти мастер и передай флаги сразу:

```
/parse https://t.me/durov -s 01.01.2024 -e 31.12.2024 -f json -k bitcoin
```

Флаги один в один как в CLI:

| Флаг | Значение |
| --- | --- |
| `-s DATE` | Начальная дата, `ДД.ММ.ГГГГ` |
| `-e DATE` | Конечная дата, `ДД.ММ.ГГГГ` |
| `-f txt\|json` | Формат вывода (по умолчанию `txt`) |
| `-l NUM` | Максимум сообщений |
| `-k WORDS` | Ключевые слова (через пробел) |
| `-j` | Убрать эмодзи |
| `-r` | От старых к новым |

(Имя выходного файла бот подставляет сам, поэтому `-o` передавать не нужно.)

### Повторная авторизация без захода на сервер

Сессии Telegram не вечны. Когда твоя протухнет, **возвращаться на сервер вообще не надо** — просто отправь боту `/auth`:

1. Бот запросит свежий код входа на твой номер.
2. Telegram пришлёт код; ты вводишь его (в формате `1 2 3 4 5` — пробелы можно, они вырезаются).
3. Если включена 2FA, дальше спросит пароль.
4. Готово — сессия обновлена.

Ради этого бот, по сути, и затевался: больше никогда не копировать коды входа через консоль сервера.

### Смена языка

Нажми 🇷🇺 **Русский** или 🇬🇧 **English** в меню `/start`. Выбор индивидуальный и применяется ко всем сообщениям, кнопкам и подсказкам дальше. (Сам Telegram к тому же покажет описания команд по-русски, если язык твоего клиента русский.)

## Прокси

Если Telegram заблокирован в регионе сервера или ты используешь платную прокси с авторизацией, можно пустить userbot через неё.

Проще всего ответить **да** на вопрос установщика «Configure a proxy?». Если хочешь добавить или поменять позже — отредактируй `.env` в папке проекта и перезапусти:

```env
PROXY_SCHEME=http
PROXY_HOSTNAME=127.0.0.1
PROXY_PORT=8080
# Только для прокси, которым нужна авторизация:
PROXY_USERNAME=your_login
PROXY_PASSWORD=your_password
```

Поддерживаемые схемы: `http`, `socks5`. Оставь `PROXY_USERNAME` / `PROXY_PASSWORD` пустыми, если прокси не требует авторизации. После правки — `docker compose restart`, чтобы применить.

## Как выглядит выгрузка

В каждом спарсенном сообщении лежит:

- `text` — текст поста или подпись к медиа (inline-ссылки из `text_link` entities попадают в скобках после якорного текста);
- `date` — `YYYY-MM-DD HH:MM:SS`;
- `views` — просмотры;
- `reactions_count` — суммарное количество реакций по всем эмодзи;
- `link` — прямая ссылка на пост (`https://t.me/channel/id`);
- `source_channel` — имя канала.

Выгрузка `json` — это массив таких объектов. Выгрузка `txt` — те же данные, но в человекочитаемом виде:

```
[2024-03-12 18:40:00] (views: 12043, reactions: 318)
Текст поста, с подставленными inline-ссылками (https://example.com).

---
```

## Режим для своих: голый CLI

Бот — это просто обёртка, а `parser.py` остаётся полностью самостоятельным CLI. И это по-прежнему правильный инструмент, если хочешь что-то заскриптовать или скормить JSON чему-то вроде n8n. Внутри контейнера (или где угодно, где установлены зависимости) он работает ровно как раньше. Благодаря `--stdout` можно гнать JSON прямо в другой инструмент из ноды Execute Command и передавать дальше по цепочке.

```bash
# Авторизация (один раз — создаёт сессию)
python parser.py --auth

# Базовый парсинг всего канала
python parser.py https://t.me/channel_name

# Диапазон дат + лимит + JSON, с именем файла
python parser.py -s 01.01.2024 -e 31.12.2024 -l 500 -f json -o export_2024 https://t.me/channel_name

# Фильтр по ключевому слову, без эмодзи
python parser.py https://t.me/channel_name -e 01.02.2026 -o grace_info -f json -j -k GRACE

# Вывод JSON в stdout (для пайпинга в n8n / jq / что угодно)
python parser.py --stdout -f json -l 10 https://t.me/channel_name

# Несколько каналов за один запуск
python parser.py -f json -o combined https://t.me/channel1 https://t.me/channel2
```

Запустить внутри работающего контейнера:

```bash
docker exec -it grabogram python parser.py --stdout -f json -l 10 https://t.me/durov
```

### Аргументы CLI

- `channel` — один или несколько URL каналов (обязателен, кроме режима `--auth`);
- `-a, --auth` — режим авторизации;
- `-s START` — начальная дата `ДД.ММ.ГГГГ` (по умолчанию: `01.01.1970`);
- `-e END` — конечная дата `ДД.ММ.ГГГГ` (по умолчанию: текущая дата; весь конечный день включается целиком);
- `-o OUTPUT` — имя выходного файла (по умолчанию: `result`);
- `-f {txt,json}` — формат файла (по умолчанию: `txt`);
- `-l LIMIT` — максимальное количество сообщений на канал;
- `-r, --reverse` — записывать результат от старых к новым;
- `-j, --no-emoji` — удалить emoji из текста;
- `-k WORD [WORD ...]` — оставить только посты, содержащие хотя бы одно ключевое слово (регистронезависимо);
- `--stdout` — вывести JSON в stdout вместо сохранения в файл.

**Куда падают файлы:** если передать только имя (`-o report`), CLI сохранит в папку `Downloads` пользователя (`report.txt` / `report.json`). Передашь путь — сохранит туда. С `--stdout` файл не создаётся вовсе. *(Когда парсер запускает бот, он сам управляет путём вывода и отдаёт тебе файл в чат.)*

## Справочник по настройкам (.env)

Установщик пишет этот файл за тебя, но вот что значит каждый ключ:

```env
API_ID=123456
API_HASH=your_api_hash
PHONE_NUMBER=+79991234567

TELEGRAM_BOT_TOKEN=123456789:ABC-DEF1234...
TELEGRAM_BOT_OWNER_ID=987654321

DATA_DIR=/app/data
OUTPUT_DIR=/app/tmp

PROXY_SCHEME=
PROXY_HOSTNAME=
PROXY_PORT=
PROXY_USERNAME=
PROXY_PASSWORD=
```

| Ключ | Для чего |
| --- | --- |
| `API_ID`, `API_HASH` | Telegram API credentials с my.telegram.org |
| `PHONE_NUMBER` | Аккаунт, который парсит (с кодом страны) |
| `TELEGRAM_BOT_TOKEN` | Токен твоего бота от @BotFather |
| `TELEGRAM_BOT_OWNER_ID` | Твой числовой Telegram ID — только этот пользователь может пользоваться ботом |
| `DATA_DIR` | Где хранится userbot-сессия (сохраняется в Docker-volume) |
| `OUTPUT_DIR` | Временная папка для выгрузок (чистится автоматически) |
| `PROXY_*` | Опциональные настройки прокси (см. выше) |

## Управление сервером

В быту тебе это не понадобится, но пусть будет:

```bash
docker logs grabogram        # логи
docker compose restart       # перезапуск (например, после правки .env)
docker compose down          # остановить
docker compose up -d         # запустить
docker compose build         # пересобрать после обновления кода
```

### Библиотеки

Из `requirements.txt`:

- `kurigram` — Telegram-клиент (API в стиле Pyrogram)
- `tgcrypto==1.2.5` — быстрая MTProto-криптография
- `aiohttp==3.9.5`, `requests`
- `python-dotenv` — загружает `.env`
- `aiogram==3.13.0` — фреймворк бота

> **Про `kurigram`:** в коде мы импортируем `from pyrogram import Client`, но ставим `kurigram`. Это намеренно — `kurigram` это поддерживаемый, совместимый с Pyrogram клиент, так что код читается как привычный Pyrogram, а установка тянет исправленный форк. Он отвечает за авторизацию, поиск каналов и чтение истории (`get_chat_history`).

## Как это работает внутри

1. В контейнере крутится `bot.py`, который опрашивает Telegram на предмет твоих команд.
2. Когда ты пишешь `/parse`, бот собирает нужные CLI-аргументы и запускает `parser.py` как подпроцесс.
3. Парсер находит канал(ы), читает историю от новых к старым, фильтрует по дате, нормализует пробелы, извлекает inline-ссылки, по желанию убирает эмодзи и применяет фильтр по ключевым словам.
4. Результат пишется во временный файл, который бот отправляет тебе документом и затем удаляет.
5. `/auth` общается с Telegram напрямую, чтобы обновить сессию в `DATA_DIR` — ту самую, которую потом использует `parser.py`.

## FAQ и полезно знать

- **История читается от новых к старым**, а `-r` разворачивает результат перед сохранением.
- **Сообщения без текста пропускаются.**
- **Ничего не нашлось?** Бот скажет «сообщений не найдено», и файл не создастся.
- **Ботом может пользоваться только владелец.** Любого другого, кто ему напишет, бот молча игнорирует — за это отвечает фильтр по `TELEGRAM_BOT_OWNER_ID`.
- **Сессии лежат на твоём сервере**, в Docker-volume. Они никогда его не покидают.
- **Одна задача за раз.** Если парсинг уже идёт, бот попросит подождать, а не станет ставить задачи одну на другую.
